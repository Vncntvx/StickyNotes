# Feature Specification: 独立笔记窗口原生镀铬与自适应重设计（Native Toolbar + Liquid Glass）

**Feature Branch**: `004-note-window-native-redesign`

**Created**: 2026-08-10

**Status**: Draft

**Input**: User description: "Redesign the standalone note window UI of the macOS sticky-note application so that it behaves and feels like a first-class native macOS 27 application, with a strong focus on window resizing, native toolbar behavior, Liquid Glass, content-first visual hierarchy, and predictable adaptive behavior. This feature is a redesign of the existing note window, not a redesign of the entire application. …"（完整描述见会话输入：原生窗口镀铬、优先级自适应、Liquid Glass 层级、内容优先、320–2000+ pt 全宽度可用、16 条成功标准）

## 背景与问题

**既有架构**（本特性不推翻）：每条笔记打开在标准 `.titled` NSWindow；`NoteWindowCoordinator.open(noteId:)` 负责创建，`NoteWindowDelegate` 负责生命周期与帧持久化（001 FR-032），`NoteWindowBridge` 维护窗口注册表/集合行为，`WindowLevelBridge` 维护置顶行为，`NoteWindowHostModel`（@Observable）驱动窗口 UI 状态；SwiftUI 内容经 NSHostingView 承载，根视图为 `NoteWindowContent`，包含 `NoteControlsView`（标题、颜色、透明度、字号、置顶、相机、附件、关闭）、`RichTextBlockView`/`RichTextView` 编辑器与块视图。

**待解决问题**：当前 `NoteControlsView` 在水平缩放时行为差——窄宽度下控件收缩、截断、不可预测消失或意外换行，数值控件产生无意义截断值（如 "100%" → "10…"）；宽宽度下控件与标题向中心漂移，而编辑器仍对齐窗口边缘，工具栏与内容看起来属于两套坐标系。既有实现把响应式当作"对一个自定义工具栏布局的连续压缩"。

**解决方向**：以原生 macOS 自适应模型取代之——标准标题栏 + 系统窗口工具栏承载常驻动作，优先级驱动的系统溢出；笔记内容始终是视觉主体；自定义布局逻辑整体减少而非增加。

## 关键解释决策（Clarifications）

用户描述自足；初稿解释决策与 2026-08-10 澄清会话决策如下（若与实现冲突需回退到会话描述原文）：

- **取代 003 假设**：003 规格假设"笔记窗口无独立工具栏外观"（003 Assumptions / FR-040/FR-041 语义）。本特性按描述明确改用"标准 macOS 标题栏 + 系统窗口工具栏模型"，该假设对笔记窗口镀铬层被本特性显式取代；003 FR-040（红绿灯与窗口行为）、FR-041（笔记表面为内容层）其余语义保持。
- **标题编辑归属**：标题**仅**在笔记内容顶部首行呈现并可直接编辑（Apple Notes 模式：首行即标题，视觉上与正文区分——加粗加大、空时灰色占位）；标题栏不渲染标题文本；`window.title` 仍派生赋值（Mission Control/窗口菜单/VoiceOver），不在标题栏发明新的就地编辑交互（macOS 无原生可编辑标题栏文本约定）。
- **格式化上下文形态**：默认采用"文本选择/光标进入格式化上下文时出现的紧凑上下文控件组 + 原生菜单命令"组合；具体控件形态（popover/检查器/紧凑控件组）由计划阶段在 FR-012 约束内选择，本规范不固定像素形态。
- **既有控制迁移**：`NoteControlsView` 常驻控件行随本特性被原生工具栏取代；该视图可移除、大幅缩减或改作上下文控件用途（用户描述明确允许）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 原生镀铬的独立笔记窗口（P1）

用户从 Library 或快捷键打开一条笔记：窗口是标准 macOS 窗口，笔记标题（或内容首行派生的标题）直接显示在内容顶部首行（Apple Notes 模式，可编辑），标题栏干净无标题文本；工具栏安静地停着少数几件事——置顶、外观、插入；没有自定义的红色 "X"，关闭走红绿灯；笔记内容从标题栏下方直接开始，视觉上笔记本身才是主角。

**Why this priority**: "打开笔记的第一眼是标题与内容而非一行编辑控件"是本特性的首要目标；原生镀铬 + 内容优先决定其余一切交互的观感。

**Independent Test**: 打开一条有标题/无标题笔记 → 验证内容首行标题（唯一可见、可编辑）、标题栏无标题文本、工具栏四项（置顶/外观/插入/溢出）、无自定义关闭按钮、内容首行贴近工具栏 → 全部可独立验证并交付"原生第一观感"。

**Acceptance Scenarios**:

1. **Given** 任意一条笔记，**When** 用户打开其独立窗口，**Then** 窗口使用标准 macOS 标题栏与系统窗口工具栏作为唯一顶层镀铬（003 FR-040 红绿灯语义保持），**And** 窗口内不存在自定义 "X" 关闭按钮，关闭仅经红绿灯（001 FR-006 语义不变：关闭隐藏窗口、保留笔记）。
2. **Given** 有手动标题的笔记，**When** 打开窗口，**Then** 内容顶部首行呈现该标题（唯一可见标题，加粗加大与正文区分，长标题在标题行内尾截断）；**Given** 无手动标题的笔记，**When** 打开窗口，**Then** 内容顶部标题框为空（灰色占位「标题」）；标题栏始终不渲染标题文本；`window.title` 基于手动标题/内容首行派生（001 FR-020/FR-021 摘要语义复用）供 Mission Control/窗口菜单/VoiceOver。
3. **Given** 打开笔记窗口，**When** 用户观察工具栏，**Then** 常驻控件收敛为置顶 / 外观 / 插入 / 更多（系统溢出）四类逻辑入口，**And** 没有颜色、透明度、字号、相机、附件各自独占独立常驻按钮（001 FR-040/FR-041a/FR-043a/FR-050 能力经聚合入口完整保留）。
4. **Given** 打开的笔记窗口，**When** 用户查看内容区顶部，**Then** 内容首行与标题栏/工具栏区域视觉相连，**And** 两者之间不存在大块常驻空白带（003 FR-042 量化阈值不回归）。
5. **Given** 窗口被激活/失活切换（多笔记窗口并存），**When** 用户比较两者，**Then** 失活窗口呈现 macOS 预期的失活外观且内容保持可读（003 FR-045 语义）。

### User Story 2 - 320 到 2000+ pt 始终是同一个窗口（P1）

用户把笔记窗口从极窄的便利贴形状拖到极宽：窗口始终是同一个连贯的 macOS 笔记窗口。窄时工具栏先让弹性空白消失，再让次要动作进系统溢出，置顶坚持到最后，内容首行标题在标题行内优雅截断，任何控件都不畸形、不截断数值、不换行；宽时工具栏不向中心漂移，额外宽度变成呼吸空间与编辑器空间。

**Why this priority**: "缩放永不显得像变成另一个界面"是本特性要解决的核心问题（描述 Problem to Solve）；优先级自适应决定成功标准 1/2/3/16。

**Independent Test**: 将窗口从 320 pt 连续拖到 2000+ pt，在既定宽度清单逐点检查无畸形/裁剪/截断数值/重叠/换行/功能不可达 → 可独立验证。

**Acceptance Scenarios**:

1. **Given** 笔记窗口，**When** 用户把窗口宽度从 320 pt 连续拖到 2000+ pt 再拖回，**Then** 任意宽度下都不存在：截断的数值（如 "100%" 变 "10…"）、部分裁剪的控件、无解释的图标碎片残留、控件重叠、控件意外换行、因窗口变窄而不可达的功能、标题栏与编辑器坐标系不一致的观感（FR-017 宽度清单：320 / 480 / 640 / 800 / 1200 / 2000+ pt）。各宽度直接可见/溢出期望（可验证操作化）：320 pt——置顶 + 插入 + 系统溢出 chevron 直接可见（标题在内容首行，不参与工具栏可见性层次，Q7），外观/更多进溢出（子菜单形态，T065）；480 pt 及以上——置顶/外观/插入/更多全数直接可见；各宽度下编辑器可用宽度与内容内边距按 FR-019。
2. **Given** 窗口变窄，**When** 水平空间不足，**Then** 按序发生：弹性空白先消失 → 低优先级动作进系统溢出 → 中优先级动作进溢出（若仍不足）→ 高优先级动作（置顶/插入）在系统可合理容纳时保持可见 → 系统溢出始终可用；控件本身绝不畸形（FR-015）。
3. **Given** 窗口变宽，**When** 宽度增加，**Then** 控件不以单一簇向中心迁移，动作区域保持稳定空间关系（标题在内容首行，不参与镀铬布局，Q7），额外宽度成为呼吸空间与编辑器空间（FR-004/FR-005）。
4. **Given** 任意窄宽度，**When** 用户需要低频率动作（导出、复制为 Markdown、移入 Trash、块特定动作等），**Then** 这些动作仍经系统溢出或原生菜单发现并可执行（003 FR-072 语义）。
5. **Given** 用户在窄宽度隐藏了某些工具栏项，**When** 用 Tab/键盘在工具栏中导航，**Then** 焦点顺序保持可预测，进入/离开溢出项的行为符合 macOS 惯例（FR-030）。

### User Story 3 - 外观：一个入口搞定颜色与透明度（P2）

用户想调整笔记观感：点一下工具栏外观入口，同一处即可选择笔记颜色、看清当前选中色、调整透明度并读到完整数值（绝不截断）、随时恢复默认；改动立即反映在笔记上。

**Why this priority**: 颜色与透明度合并、数值永不失真是描述明确的功能要求（Appearance Control 小节）；这是工具栏信息架构收缩后最重要的深层交互。

**Independent Test**: 打开外观入口 → 换色/改透明度/读数值/恢复默认 → 全部验证后关闭 → 可独立交付。

**Acceptance Scenarios**:

1. **Given** 打开笔记窗口，**When** 用户点击外观入口，**Then** 在同一界面（popover/弹出控件）中同时提供：笔记颜色选择、当前选中颜色的清晰呈现、透明度调整、当前透明度数值的无歧义完整显示、恢复默认动作（FR-008）。
2. **Given** 透明度为任意值（0–100%，Q8），**When** 用户查看数值显示，**Then** 数值完整无歧义，任何宽度下都不截断（FR-009）。
3. **Given** 用户在颜色/透明度交互中改动，**When** 改动发生，**Then** 笔记立即预览/更新（001 FR-040/FR-041a 语义不变，无确认按钮延迟）。
4. **Given** 笔记颜色为任意内置色或自定义色，**When** 工具栏/玻璃位于其上，**Then** 文本与控件保持可读（003 FR-031 对比度规则延续），**And** 工具栏图标不被笔记色过度染色（FR-026）。

### User Story 4 - 插入：一个入口聚合所有插入（P2）

用户想往笔记里加东西：点工具栏插入入口，从同一处选择截图/摄像头、图片、文件附件或支持的块类型；块插入能力与现有编辑器行为完全保留。

**Why this priority**: 相机与附件不再独立占按钮（Toolbar IA 第 3 条），但"每项可执行动作必须仍可达"是硬性要求。

**Independent Test**: 通过插入入口分别完成截图、文件附件与既有块插入 → 与 001/003 既定行为一致 → 可独立交付。

**Acceptance Scenarios**:

1. **Given** 打开笔记窗口，**When** 用户点击插入入口，**Then** 暴露截图/摄像头、图片、文件附件与支持的块类型（001 FR-050 系列能力），**And** 既有编辑器/块插入能力完整保留（003 FR-043 语义，块功能不回归）。
2. **Given** 窄窗口（如 320–480 pt），**When** 用户需要截图或附件，**Then** 该动作仍可经插入入口或菜单执行，无需独立常驻按钮（FR-010）。
3. **Given** 截图流程进行中，**When** 上下文不再适用（如取消），**Then** 上下文 UI 消失，编辑器与窗口状态保持正常（FR-028）。

---

### User Story 5 - 格式化只在需要时出现（P2）

用户选中一段文本时，格式控件（字号等）在合适的上下文 UI 出现；平时工具栏干干净净，字号不常驻占位。

**Why this priority**: 描述明确要求字号不是窗口级主动作（Text Formatting 小节）；这直接降低镀铬感知重量（成功标准 6/9）。

**Independent Test**: 选中文本 → 上下文格式控件出现并可调字号 → 取消选择/失焦后消失 → 菜单命令路径仍可用 → 可独立交付。

**Acceptance Scenarios**:

1. **Given** 编辑器内无文本选择且未进行格式化，**When** 用户观察窗口，**Then** 工具栏不存在常驻字号数值控件，格式控件视觉安静（FR-012）。
2. **Given** 用户选中文本或触发格式化，**When** 上下文 UI 出现，**Then** 暴露字号（001 FR-043a 语义）与支持的格式，**And** 控件显示完整、绝无不可读的部分标签（FR-013）。
3. **Given** 上下文不再适用（取消选择/失焦/点击他处），**When** 上下文 UI 消失，**Then** 格式化动作仍经原生菜单可达（003 FR-072 语义，FR-011）。

### User Story 6 - 键盘、无障碍与系统行为（P3）

用户只用键盘或 VoiceOver 操作笔记窗口：工具栏图标有意义的无障碍标签与 tooltip，焦点顺序随溢出稳定，重要动作在菜单中都有；Reduce Transparency / Reduce Motion / Increase Contrast / 深色模式 / 失活窗口下一切仍可理解、可用。

**Why this priority**: 系统原生适配与无障碍是本特性"系统托管自适应"原则的收尾保证（FR-030/FR-031/FR-035），也是 Constitution 无障碍与 003 FR-063 的延续。

**Independent Test**: 纯键盘走查全部工具栏项与溢出项；开启 Reduce Transparency / Increase Contrast 走查可读性；VoiceOver 读取图标标签 → 可独立验证。

**Acceptance Scenarios**:

1. **Given** 键盘用户，**When** 在工具栏与溢出项之间导航，**Then** 焦点顺序符合 macOS 惯例且可预测（FR-030）。
2. **Given** 图标型控件（置顶/外观/插入/更多），**When** VoiceOver 或指针悬停，**Then** 提供有意义的无障碍标签与 tooltip/帮助，含义可用（FR-030，001 FR-180b 语义延续）。
3. **Given** 重要工具栏动作，**When** 用户查找菜单等价物，**Then** 存在对应 macOS 菜单命令（003 FR-072 清单语义），工具栏不是唯一访问路径。
4. **Given** Reduce Transparency / Reduce Motion / Increase Contrast / 深浅色切换，**When** 用户走查窗口，**Then** 控件与内容保持可理解、可用（003 FR-063 语义延续）。

### Edge Cases

- **极窄（320 pt 最小宽度）**：一等状态（FR-017a 最小宽度 320 pt）；可见性契约见 FR-015a/FR-015b（置顶 + 系统溢出直接可见，外观与插入进溢出但可发现可执行；标题在内容首行内截断）；内容水平内边距减到最小；滚动条不消耗过高比例宽度；编辑器仍可选中/滚动/插入（FR-017/FR-021）。
- **极宽（2000+ pt）**：工具栏不整体居中漂移；内容首行标题不横向拉伸成失控间距；编辑器不居中成文档式固定列（FR-004/FR-005/FR-019）。
- **超长标题 + 窄窗口**：标题在内容首行内优雅截断（尾省略），不把任何控件推出工具栏（FR-003）。
- **透明度 100% + 窄宽度**：数值完整显示 "100%"，不出现 "10…"（FR-009）。
- **置顶切换瞬间**：选中态变化清晰可辨，工具栏布局零位移（FR-007）。
- **多个笔记窗口并存**：激活/失活外观符合 macOS，失活笔记保持可读，各自工具栏状态独立（FR-029）。
- **缩放中间态**：任何连续中间宽度都不出现部分裁剪的控件或无解释的图标残留（FR-015/FR-017）。
- **系统外观降级**：旧版 macOS 或 Reduce Transparency 下，无玻璃效果时功能与布局完整可用（FR-035）。
- **屏幕缩放比例变化 / 显示断开**：窗口保持可用且回到既有帧持久化规则（001 FR-033 语义，FR-032）。
- **编辑器大内容量**：虚拟化/性能不回退（001 FR-072b 语义，FR-034）。

## Scope *(mandatory)*

### In-Scope

- 用标准 macOS 标题栏 + 系统窗口工具栏模型取代 `NoteControlsView` 常驻自定义控件行作为笔记窗口主镀铬。
- 窗口标题采用 Apple Notes 模式：仅在内容顶部首行呈现并可编辑（视觉区分），标题栏不渲染标题文本，`window.title` 保持派生（Mission Control/窗口菜单/VoiceOver）。
- 工具栏信息架构：置顶 / 外观 / 插入 / 更多（系统溢出）四类逻辑入口；颜色+透明度合并；格式化转上下文；移除自定义关闭按钮。
- 优先级驱动的自适应层次与既定宽度清单（320 / 480 / 640 / 800 / 1200 / 2000+ pt）的全部验收。
- 编辑器布局与滚动行为调整（自适应内边距、原生滚动条、内容与镀铬视觉相连）。
- Liquid Glass 按功能层级应用于控件层（原生工具栏外观优先；自定义玻璃仅限真正浮于内容之上的控件，成组、可交互、不手工复刻）。
- 现有动作全部可达（溢出/菜单/上下文 UI），置顶、外观、插入、格式化、帧持久化、生命周期行为保留。
- `NoteControlsView` 的移除/缩减/改作上下文用途；涉及模块职责迁移（标题/置顶/外观/插入控制迁入原生层）。
- 无障碍、菜单命令、激活/失活、系统外观适配、平台 API 保真与降级。

### Out-of-Scope

- 不重设计笔记数据模型、不替换 NSTextView/富文本存储、不重设计全部块类型、不引入仅用于外观的自定义 NSWindow 子类、不做跨平台工具栏、不模仿 iOS 导航栏、不把整条笔记变成透明玻璃、不引入自定义窗口关闭按钮、不添加与交互无关的装饰动画、不要求既有笔记动作全部常驻可见（描述 Non-Goals 原样采用）。
- 不重设计 Library / 设置 / Trash / 菜单栏窗口（003 已交付范围）。
- 不改变同步引擎、加密、契约 schema（003 FR-090 语义）。
- ~~不改变 WidgetExtension 呈现（003 Assumptions 语义）。~~（WidgetExtension 已移除 2026-08-13；本特性的 More 菜单不再含 widget 项，T022 已同步。）

## Requirements *(mandatory)*

### Functional Requirements

**原生窗口镀铬**

- **FR-001**: 笔记窗口 MUST 使用标准 macOS 标题栏与系统窗口工具栏模型作为唯一顶层窗口镀铬；标准红绿灯 MUST 是唯一的窗口关闭/最小化/缩放主控件（003 FR-040 语义保持：窗口移动/缩放/最小化/关闭语义不回归）。
- **FR-002**: 自定义行内关闭按钮（现有控件行尾部 "X"）MUST 被移除；关闭窗口 MUST 仅经标准 macOS 窗口行为（001 FR-006 语义不变：关闭隐藏窗口并保留笔记）。
- **FR-003**（Q7 修订）: 笔记窗口 MUST 呈现简洁有用的标题且**仅出现一次**（Apple Notes 模式）：标题 = 内容顶部首行标题框（唯一可见呈现），有手动标题时显示该标题，空时显示本地化灰色占位「标题」（zh-Hans/en，001 FR-180a 语义），视觉上 MUST 与正文区分（加粗、加大）；标题与正文 MUST 共用同一条左边线（同一水平起点，无错位层级，SC-004）；标题行内长标题 MUST 优雅截断（尾省略）且绝不推动任何控件进入损坏状态；标题栏 MUST NOT 渲染标题文本（`titleVisibility = .hidden`），MUST NOT 在标题栏发明新的就地编辑交互；`window.title` MUST 仍派生赋值——手动标题 → 内容首行 → 本地化兜底「无标题笔记」（001 FR-020/FR-021 摘要语义复用）——供 Mission Control/窗口菜单/VoiceOver；编辑语义不变：内容顶部标题输入框（001 FR-050 "可选标题"），输入为空 MUST 写回 nil，新笔记打开时标题框获焦（001 FR-007a 语义保持），标题框不参与工具栏布局。标题同步时机：MUST 在窗口打开时、`Note.title` 变化时、无标题笔记的内容首行变化时（blocks 变化触发）实时更新 `window.title`——字符串级派生计算，无需去抖（FR-034 性能语义）。
- **FR-004**: 工具栏 MUST NOT 整体水平居中，MUST NOT 被约束在任意居中的最大宽度容器内；重要动作保持稳定工具栏区域，可用宽度由系统弹性间距吸收（窗口身份标题在内容首行，不参与镀铬布局，Q7）。
- **FR-005**: 窗口宽度增加 MUST 主要转化为弹性空白与编辑器空间；动作区域 MUST 保持稳定空间关系，不以单一簇向中心迁移（标题在内容首行，不参与镀铬布局，Q7）。

**工具栏信息架构**

- **FR-006**: 常驻顶层控件 MUST 收敛为四类逻辑入口：置顶（Pin）、外观（Appearance）、插入（Insert）、更多（More，经系统溢出/原生菜单），配合系统溢出行为；颜色与透明度 MUST 合并为一个外观入口（001 FR-040/FR-041a 能力完整保留），不得再占两个常驻大控件。
- **FR-007**: 置顶 MUST 保持为高优先级动作：窄宽度下在系统可合理容纳的范围内最后进溢出（001 FR-034 按笔记独立配置语义不变，行为经既有 WindowLevelBridge 提供）；选中态 MUST 清晰可辨且不单靠文字传达（tooltip/无障碍标签/填充态等，001 FR-044、003 FR-044 语义）——选中态 MUST 以符号变化（pin ↔ pin.fill）为主表达，MUST NOT 以大面积按钮染色表达（T067，2026-08-13）；切换置顶 MUST NOT 改变工具栏布局。
- **FR-008**: 外观入口 MUST 在同一交互中提供：选择笔记颜色、清晰呈现当前选中颜色、调整透明度（0–100% 步 5，Q8 2026-08-13——001 FR-041a 原 40–100% 下限取消）、无歧义显示当前透明度数值、恢复合理默认；修改 MUST 立即预览/更新笔记（001 FR-040/FR-041a 语义不变）。恢复合理默认 MUST 定义为：`NotePalette` 默认色键 + `transparency = 1.0`（确定性、可单测）。透明度语义（Q9，2026-08-13，取代 T073 的内容层淡化）：透明度 MUST **仅作用于背景**（纸面/窗口背景）；文字与内容 MUST 保持全不透明，任何透明度下（含 0%）都清晰可读——0% 时纸面消失、文字完整浮于桌面之上；MUST NOT 经 `window.alphaValue` 实现（原生镀铬不淡化，FR-025）。
- **FR-009**: 透明度数值 MUST 在任何宽度下完整显示，绝不截断（禁止 "100%" → "10…"）。
- **FR-010**: 插入 MUST 是单一逻辑入口：工具栏"插入"项 MUST 打开原生下拉菜单，聚合截图/摄像头、图片、文件附件与支持的块类型（001 FR-050 系列能力完整保留）；插入目标解析：富文本块内光标/选区 → 于光标处拆分该块并插入（保留格式属性），特殊块焦点 → 插于该块之后，无活动插入点 → 追加至内容末尾；编辑器内的块插入控件（003 FR-043 语义：插入点附近微妙添加控件）MUST 保留为上下文路径，与窗口级插入入口并存但不重复；相机与附件 MUST NOT 在窄宽度下作为独立常驻按钮。异步插入流程（截图捕获/文件选择）MUST 在发起时快照解析后的插入目标；完成后若窗口已关闭或内容上下文已失效，MUST 安全降级为末尾追加，绝不部分插入或损坏内容；IME 组合期间（marked text）MUST NOT 在组合文本处拆分块——目标解析安全推迟至组合结束后落位，否则降级末尾追加。
- **FR-011**: 低频动作 MUST 归入原生菜单、系统溢出或显式「更多」菜单项（FR-006），MUST NOT 消失；离开可见工具栏的每个动作 MUST 仍可发现、可执行；每个重要工具栏命令 MUST 有对应 macOS 菜单命令（003 FR-072 语义延续）。
- **FR-012**: 字号（001 FR-043a 语义）MUST NOT 作为窗口工具栏常驻控件（任何宽度）；格式化 MUST 为上下文行为：格式控件 MUST 在以下情况出现——用户选中文本，或用户通过菜单/快捷键触发格式化命令；控件形态为锚定在选择/编辑器附近的紧凑上下文控件组（具体形态由计划阶段选择，FR-022 玻璃约束内）；格式菜单与既有格式化快捷键 MUST 始终可用（稳定入口），因此取消选择/失焦时上下文 UI 消失是允许的；无格式化进行中时 MUST 视觉安静。无选区时格式化命令 MUST 作用于 typingAttributes（对后续输入生效），而非禁用；IME 组合期间（marked text）MUST NOT 应用格式、MUST NOT 发布选区（菜单与快捷键命令同样受此守卫）；窗口失活时上下文浮动行 MUST 隐藏，重新激活且选区仍在时恢复显示。
- **FR-013**: 格式化控件 MUST NEVER 收缩为不可读的部分标签或截断数值。

**响应式与缩放**

- **FR-014**: 窗口 MUST 支持连续交互式缩放；MUST NOT 通过控件压缩至内容截断来实现响应式；MUST NOT 允许工具栏控件意外换行到多行。弹出控件（外观 popover/工具栏菜单）打开期间缩放窗口：行为 MUST 跟随系统默认（菜单随几何变化关闭；popover 按系统规则重锚定或关闭），不得崩溃、布局错乱或产生部分应用值（外观改动即时生效，无确认态）。
- **FR-015**: MUST 采用优先级自适应层次：水平空间减小时按序——①弹性空白消失 ②低优先级动作进系统溢出 ③中优先级动作进溢出（如仍不足）④高优先级动作（置顶/插入）在系统可合理容纳时保持可见 ⑤系统溢出始终可用；⑥控件本身绝不畸形。（标题在内容首行，不参与工具栏可见性层次，Q7。）
- **FR-015a**: MUST 采用如下显式语义优先级模型（映射到原生工具栏可见性行为，不依赖手写像素断点）：**置顶**、**插入** = 高优先级，系统可合理容纳时始终直接可见（2026-08-13 T065 修订：窄窗口保留两个主命令，外观/更多进系统溢出）；**外观**、**更多** = 中优先级，空间不足时移入系统溢出（溢出形态为子菜单，低频动作经子菜单完整可达，不出现产品级"…"被困于系统"»"的两层菜单）；**格式化等编辑控件** = 绝不作为常驻工具栏项（FR-012 上下文语义）；每个重要动作 MUST 同时存在菜单命令（003 FR-072 语义）。（标题不在本模型内——Q7 起标题仅存在于内容首行，FR-003。）
- **FR-015b**: 最小宽度（320 pt，Q6）下 MUST 直接可见：置顶、插入、系统溢出图标；外观与更多 MUST 允许仅存于溢出但 MUST 保持可发现、可执行（FR-016）；不得移除任何功能的访问路径。产品保证与系统裁量边界：产品义务 = 置顶/插入保持最高可见性优先级（系统可合理容纳范围内最后进溢出，FR-015④）+ 每个动作经溢出子菜单形态完整可达；直接可见性在系统物理容纳范围内受系统裁量。若系统溢出 chevron 物理上无法容纳置顶（系统硬约束），唯一允许的回退 = 将置顶优先级提升至最高档（单一常量，非手写断点）；验收判定 = 置顶直接可见，或（系统物理无法容纳时）经溢出菜单可见且选中态正确。（标题条款随 Q7 移至 FR-003：标题在内容首行内截断，完整标题经标题框 accessibility 值可读。）
- **FR-015c**: 笔记窗口工具栏 MUST 由产品固定、不可由用户自定义（不启用原生工具栏定制）；核心项（置顶/外观/插入）不得被用户重排或移除，系统原生溢出/自适应行为仍适用；MUST NOT 持久化任何工具栏排列状态（无全局/按笔记之分）；按笔记持久化的状态仅限笔记级属性（置顶、颜色、透明度、标题），临时 UI 状态（打开的弹出控件、上下文格式化状态）MUST NOT 持久化。
- **FR-016**: MUST NOT 在任意像素断点手动隐藏功能而无替代访问路径；MUST NOT 使任何功能仅因窗口变窄而不可达。
- **FR-017**: 窗口 MUST 在 320 / 480 / 640 / 800 / 1200 / 2000+ pt 宽度全部可用且过渡连续、有意为之；上述任意宽度禁止：截断的数值数据、部分裁剪的控件、无解释的图标碎片残留、控件重叠、意外换行、窄宽度功能不可达、标题栏与编辑器坐标系不一致的观感。
- **FR-017a**（Q6 修订）: 窗口 MUST 以 320 pt 为实际最小宽度（AppKit 强制，用户不得缩到更窄），并设置最小高度 140 pt；320 pt 是受支持的一等窄态（美观的常规最小值，长标题在内容首行内截断）；设计无需在 320 pt 以下继续降级。原 220 pt 最小宽度（2026-08-10 Q1）被 2026-08-13 Q6 取代。

**编辑器布局与滚动**

- **FR-018**: 编辑器内容 MUST 自然延伸通过可用笔记表面，与标题栏/工具栏区域视觉相连；MUST NOT 在窗口镀铬与笔记内容之间保留大块常驻空白带（003 FR-042 语义：首行紧贴顶部的量化阈值不回归）。
- **FR-019**: 内容内边距 MUST 自适应：窄宽度减少水平内边距以保留可用文字宽度，宽宽度适度增加呼吸空间；MUST NOT 将笔记文字居中成文档式固定宽度列（除非编辑器设计另有要求）。语义值（唯二状态）：compact = 10 pt 水平内边距（窄宽度）、regular = 14–16 pt（宽宽度），以窗口宽度 480 pt 切换；极宽上限 24 pt（防居中列）——此为本特性唯一允许的宽度感知规则（NSToolbar 无法表达内容内边距）。
- **FR-020**: 滚动 MUST 使用原生 macOS 滚动行为与系统滚动条外观；MUST NOT 绘制常驻高对比滚动条轨道；窄宽度下滚动条 MUST NOT 消耗过高比例编辑器宽度；滚动、文本选择、插入与富文本行为 MUST 全部正常。

**统一编辑上下文（2026-08-13 修复：Todo/Code Block 插入破坏编辑连续性）**

- **FR-036**: 块插入 MUST 不改变正文编辑表面：Todo/Code Block MUST 作为内容节点内联插入同一纸面流，MUST NOT 把正文拆分为上下两个独立"纸面"区域；caret-split 产生的尾部富文本块 MUST 内容自适应高度（无 320pt 最小纸面高度）；主编辑面的 320pt 最小纸面高度 MUST 仅在其是笔记全部内容（无后续块）时生效——有块跟随即内容自适应，插入后 MUST NOT 出现大段空白或第二套块页面布局。
- **FR-037**: 统一撤销/重做：每便签窗口 MUST 拥有一个共享 UndoManager，全部块编辑器（正文/todo/code）与全部结构变更共用；⌘Z/⌘⇧Z MUST 覆盖块插入/删除/移动/勾选/缩进与块内文本编辑；结构变更（插入/删除/移动/勾选/空块移除）MUST 注册为单个独立撤销组——⌘Z 恢复变更前文档状态、⌘⇧Z 重放；结构变更 MUST NOT 清空此前累积的逐字输入撤销——保留完整交错历史（2026-08-13 用户实测修订：早前"清空"决策导致 ⌘Z 只剩两三次）；结构组 MUST 以 `groupsByEvent=false` 暂态注册为独立顶层组（避免与相邻动作落入同一隐含事件组合并成一步）；撤销/重做的持久化副作用（TodoItem 行、FileLocator 行）MUST 与块列表同步恢复；模型推送 MUST NOT 产生撤销动作、MUST NOT 清空撤销栈。
- **FR-038**: 格式命令路由 MUST 作用于当前聚焦的富文本编辑器（非恒为主编辑器）：⌘B/⌘I/⌘U 经每便签选区桥路由到焦点所在块（正文/todo/尾部块）；无选区时作用于 typingAttributes；纯文本块（code）中富文本格式命令 MUST no-op（等宽纯文本契约，FR-080）；斜体 MUST 对无 italic 字面的字体（如 CJK PingFang）生效——经 `.obliqueness` 合成倾斜（NSFont 丢弃 descriptor matrix、NSFontManager 无法为无字面家族合成，2026-08-13 实测 ⌘I 失效根因）；非聚焦编辑器的过期选区/失焦事件 MUST NOT 覆盖聚焦编辑器状态；聚焦编辑器自身失焦时上下文浮动行 MUST 隐藏（选区保留，FR-012 语义）。
- **FR-039**: 插入完成后 First Responder MUST 移入新插入的文本块（Todo/Code），光标位于内容开头——插入即连续输入（2026-08-13 已确认决策）；截图/图片/文件等非文本块插入 MUST NOT 抢占焦点。
- **FR-040**（FR-080/FR-081 扩展）: Code Block MUST 可编辑——等宽纯文本编辑器（NSTextView, `isRichText = false`），编辑写入 `CodePayload.text`（language 保留）；与正文/todo 同属统一编辑上下文（共享 UndoManager、选区桥焦点发布 `focusedSpecialBlockId` → 插入目标 `.afterBlock`、插入后焦点请求）；复制按钮 MUST 继续复制纯代码文本。
- **FR-041**: Todo 文本 MUST 为完整富文本编辑面（替换原纯文本 TextField）：run 标记（bold/italic/underline/strikethrough/inlineCode/link）在编辑往返中保留（FR-053 语义）；完成态删除线/次要色 MUST 为显示专用样式，MUST NOT 写入 canonical 模型 marks；todo 行编辑/勾选/删除/移动全部进入统一 Undo history。
- **FR-042**: 选区发布的光标偏移 MUST 为 Unicode scalar 偏移：NSTextView 的 UTF-16 码元偏移 MUST 在发布前转换（CJK/emoji 光标处拆分不得错位）；块拆分函数维持 scalar 偏移语义不变（FR-010/R3）。

**Liquid Glass**

- **FR-021**: 窗口 MUST 采用 macOS 27 原生 Liquid Glass 设计语言但遵循 Apple 层级：玻璃表示浮于内容之上的功能控制/导航层；笔记正文 MUST NOT 变为玻璃面板；笔记内容/背景保持内容层并提供笔记颜色身份（003 FR-041/FR-060 语义延续）。
- **FR-022**: 系统提供的工具栏/控件 MUST 使用系统原生 Liquid Glass 外观；自定义 Liquid Glass MUST 仅用于真正浮于内容之上且标准工具栏/控件无法表达交互的控件（003 FR-044 语义延续）；邻近自定义玻璃控件 MUST 作为逻辑组呈现（如成组表面），而非无关的半透明胶囊集合。
- **FR-023**: 可交互的自定义玻璃控件 MUST 提供 macOS 27 交互响应；MUST NOT 用模糊/渐变/边框/阴影/半透明矩形手工复刻 Liquid Glass（当原生处理可用时）；MUST 避免过度玻璃——少量有意义的玻璃表面优先于逐个图标包裹玻璃。

**几何与角部**

- **FR-024**: 窗口形状与系统圆角几何 MUST 被尊重；靠近窗口角落的自定义浮动控件 MUST 视觉跟随窗口/容器角曲率而非无关固定圆角半径；MUST NOT 使用在一个尺寸正确、在另一尺寸与系统窗口形状冲突的硬编码几何。

**颜色、置顶与激活状态**

- **FR-025**: 笔记颜色 MUST 保留其内容层身份（001 FR-040 语义）：颜色自然影响其上原生半透明工具栏/玻璃外观，无需单独绘制假工具栏背景；文本与控件在全部支持颜色上 MUST 保持可读（003 FR-031 对比度规则延续）；MUST NOT 过度给每个工具栏图标染笔记色。窗口背景 MUST 应用与纸面一致的透明度（`windowBackground` 经 `note.transparency` 统一），构成单一内容层，transparency < 100% 时标题栏条带与纸面之间 MUST NOT 出现可见接缝；透明度 MUST NOT 经 `window.alphaValue` 实现（不得连原生镀铬一起淡化）；最坏可读性验证 MUST 覆盖 0% 透明度（最坏情形，Q8）× 全部调色板色 × 亮/暗外观（对比度规则对合成背景计算，003 FR-031 延续）。
- **FR-026**: 置顶 MUST 表现为持久笔记/窗口状态而非破坏性瞬间命令（行为经既有 WindowLevelBridge，001 FR-034 语义不变）。
- **FR-027**: 激活与失活笔记窗口 MUST 保持与 macOS 一致的可区分性（003 FR-045 语义）；MUST NOT 发明自定义重度失活态；失活笔记 MUST 保持可读。

**上下文控件**

- **FR-028**: 仅特定编辑上下文有意义的控件（文本格式化、块特定动作、截图特定动作、代码块特定动作）MUST 上下文出现而非占据常驻工具栏空间；上下文 UI MUST 使用原生 Mac 交互模式，上下文不再适用时消失。

**键盘与无障碍**

- **FR-029**: 重设计 UI MUST 保持纯键盘与指针完全可用（003 FR-063 语义）；工具栏与菜单命令 MUST 提供有意义的无障碍标签（001 FR-180b 语义延续）；SF Symbols/系统标准符号优先；图标控件 MUST 经无障碍标签与 tooltip/帮助可理解；键盘焦点顺序 MUST 随工具栏项进出溢出保持可预测；重要工具栏动作 MUST 同时经正常 macOS 菜单命令可达（003 FR-072 语义），工具栏不是唯一访问路径；既有 ⌥C/⌥O/⌥T（颜色/透明度/字号步进）快捷键 MUST 在控件行移除后继续可用。

**系统原生适配**

- **FR-030**: 工具栏溢出、尺寸、间距、激活/失活外观、控件材质、指针响应、无障碍与标准菜单行为 MUST 优先使用系统托管行为；MUST NOT 为像素级视觉控制在 SwiftUI 中复刻平台行为；本特性 MUST 减少自定义布局逻辑，而非增加更多手写断点。

**既有架构约束**

- **FR-031**: 既有职责 MUST 保持：`NoteWindowCoordinator`（窗口创建）、`NoteWindowDelegate`（生命周期/帧持久化，001 FR-032 语义）、`NoteWindowBridge`（注册表/集合行为）、`WindowLevelBridge`（置顶行为）、`NoteWindowHostModel`（窗口 UI 状态）、`RichTextBlockView`/`RichTextView` 与既有块内容（编辑器实现，不替换）。关闭→重开生命周期：任何关闭路径（红绿灯/⌘W/关闭菜单）MUST 完成——保存帧 → `NoteWindowBridge.unregister` → 释放工具栏控制器 + delegate + host（`close()` flush）；关闭后 `isOpen(noteId:)` MUST 为 false；再次 `open(noteId:)` MUST 创建全新窗口，绝不复活携带旧状态（含临时 UI 状态）的宿主。

- **FR-035**: 向后兼容 MUST 优雅降级：较旧受支持 macOS 版本可省略新视觉效果，但 MUST 保留全部功能与可用布局。

## Assumptions

- 本特性只重设计**独立笔记窗口**（描述明确）；Library/设置/Trash 等 003 已交付表面不受影响。
- 标题仅在内容顶部首行呈现并编辑（Apple Notes 模式，Q7）；标题栏不渲染标题文本；不发明标题栏内就地编辑（001 FR-050 语义不变）。
- 置顶行为语义保持（001 FR-034 按笔记独立配置），仅呈现改为原生工具栏态；行为经既有 WindowLevelBridge 提供。
- 透明度与颜色能力经外观入口保留（001 FR-040/FR-041a），字号经上下文格式化保留（FR-012）；三者的既有存储语义与默认值不变。
- 格式化上下文形态（popover/检查器/紧凑控件组）由计划阶段在 FR-012 约束内选择；菜单路径必达（FR-011）。
- 优先级层次以原生工具栏溢出/可见性机制为主实现；仅当系统机制无法表达某项确定性需求时，才允许最小限度的补充逻辑（FR-015/FR-030 约束内）。
- 平台 API 清单为规划期约束；实际可用性以安装的 macOS 27 SDK 为准（平台约束节）。
- 标准 NSWindow + 系统窗口工具栏组合的可用性已由本特性 spike 实测验证（T011，macOS 27）；Library 的 MenuBarExtra 工具栏 spike 失败源于私有窗口类，不构成 NSToolbar 在此项目不可用的证据。
- 选区观察是本特性引入的编辑器新依赖（`RichTextView` 现状无 `textDidChangeSelection`），由新 `EditorSelectionBridge` 提供只读投影；该依赖不改变编辑写路径（003 FR-043 语义）。
- macOS 26 与 27 的系统溢出/玻璃视觉差异由系统托管（plan §6 兼容矩阵），不按 OS 分叉整套窗口实现；仅围绕真正不可用的能力做 `#available` 窄守卫。
- 本规范语言遵循 002/003 先例（中文 + 英文术语/FR 引用）；交付物本地化仍为 zh-Hans/en（001 FR-180a 语义）。
